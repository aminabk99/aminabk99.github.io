Detecting credential stuffing attacks, and why picking a threshold mattered more than picking a model

January 2026 · GitHub

Python · scikit-learn · Isolation Forest · Streamlit

This is an anomaly detection system that analyzes login traffic per IP address and classifies each burst of attempts as human or bot. Login events get bucketed into one-minute windows per IP, and I extract four features per window: attempt count, failure rate, unique users targeted, and burst ratio. An Isolation Forest model trained on normal traffic scores each window, and anything flagged anomalous gets written to a log with a plain-English reason. There's a Streamlit web UI and a Tkinter desktop app, both showing a HUMAN or AI verdict instantly.

The detector is unsupervised, but I had ground truth for my simulated traffic, every event is labeled human or bot, so I could actually measure detection quality instead of just asserting it works. I built a labeled simulation of about 120 human IPs and 8 bot IPs, including loud bursts and slower stealthy attempts, and benchmarked four approaches on a held out test set of 212 windows: Isolation Forest, One-Class SVM, Local Outlier Factor, and a simple four-line rule baseline.

The results surprised me. Every model ranked attacks near perfectly, ROC-AUC around 1.00 across the board, meaning the features separate cleanly. But at each model's own default operating point, they behaved completely differently. Isolation Forest was far too conservative and missed 63% of attacks. One-Class SVM flagged basically everything, a 100% false positive rate. Local Outlier Factor happened to land right at perfect precision and recall. And the four-line rule baseline beat Isolation Forest's default threshold outright.

Hardest part: tuning the Isolation Forest's contamination parameter. Set it too low and real attacks slipped through, too high and the alert log flooded with false positives. Getting the burst ratio feature right ended up being the key to actually separating human pauses from machine-speed requests.

Most interesting part: realizing the real lesson wasn't which model to pick, it was that threshold calibration matters more than model choice. A model that ranks attacks perfectly is still useless in production if its default decision boundary is wrong. I'm being upfront that these numbers are on labeled simulated traffic, so the high AUCs reflect a separable simulation, not a production guarantee, real login streams are noisier than this.
