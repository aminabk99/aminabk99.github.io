Building a fully local coding agent with a 20-step JSON action loop

January 2026 · GitHub

Python · FastAPI · Ollama · qwen2.5-coder

This is a Python coding agent powered by Ollama and qwen2.5-coder that takes a task, breaks it into tool calls, and autonomously writes files, reads code, and runs shell commands. It works through a structured JSON action loop, up to 20 steps per task, exposed through a FastAPI /chat endpoint with a dark-themed web UI.

You send it a task, something like "write a Python script that scrapes headlines," and the agent enters the loop: each step the model returns one action as a JSON object, the agent executes it using one of four tools (list files, read file, write file, run command), appends the result to history, and loops again. After up to 20 steps it calls finish and returns the final response. Every file operation is sandboxed to a workspace folder, so nothing outside it can be touched, and shell commands run with that folder as the working directory.

Hardest part: recovering JSON from a chatty model. qwen2.5-coder sometimes wraps its JSON in markdown code fences or adds explanation text before the actual object, so a strict parser would just fail. I built a fallback parser that scans for the first { and last } in the response and tries to extract valid JSON from that slice. It handles roughly 95% of malformed outputs without needing to re-prompt the model.

Most interesting part: the 600 second timeout. On the first run, Ollama has to load the full 7B model into memory, which can take 30 to 60 seconds on a CPU. Without an extended timeout the agent would crash before the model even responded. I added a short retry message that explains what happened if it still times out, instead of just throwing an exception at the user. It's a small fix, but it's the difference between an agent that feels broken and one that feels like it's just thinking.

No API keys and no cloud calls anywhere in this one. The whole thing runs on your machine, which was the point: I wanted to know how far a fully local setup could get before it needed real infrastructure.
