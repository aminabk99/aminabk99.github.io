A Java college database, and what a team project taught me about relational integrity

January 2026 · GitHub

Java · SQLite · JDBC

This was a team project: a Java console application that models a college's core academic entities, students, faculty, courses, sections, and enrollments, with full CRUD operations backed by a SQLite database. It launches a console menu where you pick which entity to manage, and depending on the entity you can add, read, update, or in the case of enrollments, delete records.

Every operation goes through one class that uses JDBC PreparedStatements to safely execute SQL against a local SQLite file, and each entity is modeled as its own Java class with private fields, getters, setters, and a toString override.

Hardest part: managing relational integrity by hand. Enrollments reference sections, and sections reference both courses and faculty, so deleting or updating a parent record meant carefully thinking through the cascading effects ourselves, without an ORM to handle it automatically.

Most interesting part: using PreparedStatements with placeholders instead of building SQL strings by concatenation. It's a small habit, but it prevents SQL injection outright and makes the parameter binding explicit, and it's the kind of thing that matters a lot more in a real system than it looks like it should in a classroom project.
